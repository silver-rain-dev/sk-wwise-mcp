- [2026-10-04, wave 4, issue #8] Loop safety and push details of the bump step: triggers are only `push: tags: v*` and `workflow_dispatch`, so a push to `main` cannot start the workflow; the push uses the built-in `GITHUB_TOKEN` (never triggers workflows) and the message has `[skip ci]`. The step writes the file with the tagged commit's script into `$RUNNER_TEMP`, then `git fetch` + `git checkout -B main origin/main`, copies the file, commits only if `git diff --cached` is non-empty, and runs `git push origin HEAD:main`. Workflow and job permissions are `contents: write` only. Checked on 2026-10-04: `main` has no branch protection and no rulesets on silver-rain-dev/sk-wwise-mcp, and the repo default workflow token is read-only (the workflow's own `permissions` block overrides it).
  - Why: a bot push to a protected `main` would fail after the release is already published; a stale tag whose commit is not on `main` still bumps `main` (by design).
  - Affects: whoever adds branch protection later (allow the Actions bot, or bump by hand with the script); #10. Not run on GitHub yet, so the git steps of the bump are unexercised.
